# 《그리는 자의 바다 (Sea of the Pen)》 게임 개발 문서

> 버전 0.3 (프리 프로덕션) — 2026-08-05
> 장르: 2D 탑뷰 물리 퍼즐 항해 게임
> 핵심 참조: 젤다의 전설 BotW(화학 엔진의 설계 철학), Poly Bridge(실패 학습 루프), Kerbal Space Program(설계-운용 분리)

## 0. 설계 철학 (모든 결정의 상위 원칙)

본 게임의 모든 시스템은 다음 세 원칙에서 파생된다. 새 기능을 제안할 때는 반드시 이 원칙과의 정합성을 먼저 검토한다.

### 원칙 1 — 상호작용을 개별 스크립트로 만들지 않는다
BotW 화학 엔진의 본질은 "재질 × 에너지의 보편 규칙표"만 정의하고, 개별 상호작용은 규칙의 조합에서 **창발**하게 한 것이다. 본 게임도 동일하다.

- 모든 객체(선체, 아이템, 장애물)는 **재질(Material)** 을 가진다.
- 맵에는 **환경 필드(Field)** 가 흐른다 — 바람, 해류, 온도, 전기, 자기.
- 엔진에는 **재질 × 필드의 규칙표**만 존재한다.
- **맵별 특수 처리 코드는 원칙적으로 0줄.** 맵은 필드와 오브젝트의 배치일 뿐이다.

검증 기준: *개발자가 의도하지 않은 해법이 규칙 조합만으로 성립하는가?* (예: 화염 맵의 의도 해법은 철배이지만, 나무배에 '젖음' 상태를 입혀 통과하는 해법도 자동으로 성립해야 한다.)

### 원칙 2 — 순수하게 좋기만 한 속성은 없다
모든 재질·아이템·형상 선택은 트레이드오프를 가진다. 이것이 맵마다 다른 설계를 강제하는 유일한 메커니즘이다. 밸런싱 시 어떤 요소가 "항상 정답"이 되면 즉시 약점을 추가한다.

### 원칙 3 — 시스템이 이미 계산하고 있는 출력을 버리지 않는다
창발의 깊이는 기능의 개수가 아니라 **피드백 루프의 개수**에서 나온다. 물리 엔진이 이미 산출하는 값(폴리곤 형상, 무게중심, 충격량)을 다시 게임플레이의 입력으로 되먹인다. 파손 시스템(§7)이 이 원칙의 대표 적용 사례다.

## 1. 게임 개요

- **핵심 루프**: 맵 정찰 → 배 설계(선체 그리기 + 아이템 배치) → 출항 시뮬레이션 → 실패 분석 → 재설계
- **뷰**: 2D 탑뷰. 맵은 위에서 내려다본 수면이며, 바람·해류가 화면상 벡터장으로 시각화된다.
- **승리 조건**: 맵별 목표 지점 도달(기본). 화물 운송, 시간 제한 등 변형 목표는 후순위.
- **실패 설계**: 실패는 항상 "내 설계의 어떤 물리적 선택이 틀렸는가"로 귀속되어야 한다. 조작 수단 부재로 인한 실패(soft-lock)는 기본 장치(§5)로 원천 차단한다.

## 2. 선체 그리기 시스템

플레이어는 설계 캔버스에 선체 윤곽을 **폐곡선**으로 그린다. 그린 형상은 장식이 아니라 물리량으로 직접 변환된다.

### 2.1 형상 → 물리량 변환 (탑뷰 3대 파라미터)

| 파라미터 | 산출 방법 | 게임플레이 의미 |
|---|---|---|
| **저항 타원** | 형상의 방향별 투영 폭으로 전후/좌우 저항 계수 산출 | 길쭉한 배: 직진 빠름·옆밀림 적음·회전 둔함 / 둥근 배: 제자리 회전 쉬움·최고속 낮음 |
| **관성 모멘트 (I)** | 질량 분포의 무게중심 기준 제곱거리 적분 | 길거나 끝단이 무거운 배는 회전 시작·정지가 모두 어려움 |
| **흘수 (draft)** | 총 질량 ÷ 선체 면적 (부력의 스칼라 축약) | 깊으면 여울 좌초, 얕으면 강풍에 횡류 |

### 2.2 윤곽선 = 부위 규칙
윤곽의 국소 형상이 그 부위의 기능을 결정한다.
- **뾰족한 돌출부**: 충돌 데미지 집중(충각). 단, 자기 배가 받는 충격도 그 지점에 집중.
- **넓은 평면**: 대포 피탄 면적 증가, 대신 바람 받는 면적도 증가.
- 그리기가 곧 공격/방어 설계다.

### 2.3 그리기 UX 요구사항
- 캔버스에 실시간으로 무게중심(G), 저항 타원, 흘수 게이지를 오버레이 표시.
- 자기교차 곡선은 그리는 즉시 자동 보정 또는 경고.
- 최소/최대 면적 제한은 맵별 파라미터(좁은 해협 맵 등에서 사용).

## 3. 재질 시스템

선체는 영역별로 재질을 칠할 수 있다(브러시 방식). 아이템도 각자 재질을 가지며 동일 규칙표를 따른다.

| 재질 | 밀도 | 강점 | 약점 |
|---|---|---|---|
| 나무 | 낮음 | 가벼움, 저렴 | 가연성, 저내구 |
| 철 | 높음 | 고내구, 내화 | 무거움, 전기 전도, **자성** |
| 천 | 최저 | 풍압 수용(돛 전용) | 즉시 연소, 역풍 시 역추력 |
| 고무 | 중간 | 절연, 충격 흡수(반발) | 열에 용융 |
| 얼음 | 낮음 | 냉기 지대에서 무료 생성 | 열기 지대에서 소멸 |

> 원칙 2 체크: 각 재질은 최소 1개 이상의 치명적 약점을 가진다. 신규 재질 추가 시 동일 기준 적용.

## 4. 아이템 시스템

### 4.1 통일 모델
모든 아이템은 단 세 속성으로 정의된다: **부착 위치(선체 로컬 좌표) · 방향 · 질량.** 효과는 전부 이 셋과 물리 법칙에서 파생된다.

핵심 공식: **토크 = 힘 × 무게중심으로부터의 팔길이(r)**
→ "어디에 붙였는가"가 곧 조향 특성이다. 별도의 조향 시스템 코드는 만들지 않는다(기본 장치 제외, §5).

### 4.2 아이템 목록 (초기 세트)

| 아이템 | 물리 원리 | 위치·방향이 만드는 차이 |
|---|---|---|
| 부스터 | 부착 방향으로 추력 | 중심선 후미=직진 / 좌우 비대칭=자동 선회 / 측면=평행이동(게걸음) |
| 대포 | 탄환 발사 + **반동** | 뱃머리=공격 / 후미에 후향 장착=반동 추진(창발 해법 허용) |
| 방어막 | 부착면 기준 호(arc) 커버 | 커버 방향은 바람 수용 불가. 고질량 → 편측 배치 시 회전 성향 발생 |
| 돛 | 힘 = 바람벡터 · 돛법선 × 면적 × 풍압계수 | 중심선 이탈 시 바람마다 요잉 발생 |
| 키(방향타) | 물흐름 편향. **유속 0이면 무효** | 후미일수록(r↑) 효과적. 전방 부착은 거의 무용 |
| 닻 | 순간 고정점(핀 조인트) 생성 | 측면 투하 시 그 점 축 급선회(드리프트) |
| 밸러스트(추) | 순수 질량 | 관성 모멘트·흘수 조절용 |

### 4.3 트리거 바인딩
- 각 아이템에 키 바인딩 가능(부스터 점화=A, 닻 투하=B 등).
- 설계 단계에서 "언제 무엇을 작동시킬지"까지가 설계의 일부.
- 조건 트리거(파손 시 자동 점화 등)는 **차기 버전 범위**(본 문서 범위 외).

### 4.4 아이템과 규칙표
아이템도 재질 규칙의 예외가 아니다. 천 돛은 화염에 타고, 철 대포는 낙뢰를 유도하며, 자기장에서 철 아이템만 뜯겨나간다.

## 5. 기본 장치 (창발의 바닥)

**설계 근거**: 순수 창발에만 조향을 맡기면 (a) 토크를 배우려면 배를 몰아야 하는데 조향이 없어 몰 수 없는 순환 문제, (b) "설계 실패"와 "조작 수단 부재"의 실패 귀속 혼동이 발생한다. BotW가 화학 엔진과 무관하게 검·활이라는 기본 동사를 보장하듯, 본 게임도 기본 동사를 보장한다.

### 5.1 자동 부착 3종 (선체 확정 시 자동 장착)

| 장치 | 사양 | 학습 기능 |
|---|---|---|
| 기본 키 | 후미 중심선, 나무 재질. **유속 비례 선회력** (정지 시 무효) | "키는 물살이 있어야 듣는다"를 장치 자체가 교육 |
| 기본 노 | 미약한 무풍 추력. 맵 클리어 불가 수준 | soft-lock 방지 전용 |
| 기본 닻 | 정지 수단 | 해류 맵에서 "멈추고 생각하기" 보장 |

### 5.2 밸런싱 3원칙
1. **기본 장치만으로 어떤 맵도 클리어 불가** — 기본 키의 선회력은 잔잔한 물 기준으로 산정, 강해류·강풍에서 역부족하도록 수치 고정.
2. **탈착·교체 가능** — 숙련자는 기본 키를 제거해 무게·저항을 절감하고 자체 조향계(부스터/반동/닻)를 구성. "보조 바퀴 떼기"가 실력 표현이 된다.
3. **규칙표 예외 없음** — 기본 키(나무)는 화염 지대에서 소실 가능. 조향 상실이 창발 이벤트가 된다.

## 6. 논리 엔진 (3층 구조)

### 6.1 ① 환경 필드
맵 = 벡터장/스칼라장의 집합.
- 벡터장: 바람(방향+세기), 해류
- 스칼라장: 온도, 전기, 자기
- 장애물은 필드를 국소 변조하는 장치일 뿐이다. (화산 = 온도 상승 + 화염 파티클 / 폭풍 = 시변 회전 바람 벡터)

### 6.2 ② 상태 전파
객체 상태: `불붙음 / 젖음 / 대전됨 / 결빙` 등.
- 접촉·근접으로 전파. 상태 간 상성만 정의(젖음은 불붙음 해제, 대전은 금속 전도 등).

### 6.3 ③ 규칙표 (재질 × 필드/상태)
- 20~30개의 보편 규칙. 예: `천 + 바람 = 추력 발생`, `나무 + 불 = 연소 후 파괴`, `철 + 전기 = 전도`, `철 + 자기장 = 인력`.
- **규칙표는 JSON 등 데이터로 외부화** — 밸런싱을 코드 수정 없이 수행.
- 게임의 심장부. 맵별 특수 코드 0줄 원칙의 실현 수단.

## 7. 파손 지오메트리 시스템 ★ 신규

### 7.1 설계 근거 (원칙 3의 적용)
배는 이미 폴리곤이다. 따라서 데미지를 추상 수치(HP)로 처리할 이유가 없다. **피해 = 폴리곤 형상의 실제 변형**으로 정의하면, 기존 물리 규칙(§2.1)에 신규 코드 추가 없이 다음이 전부 창발한다.

### 7.2 사양

**입력**: 충격 이벤트(대포알 피격, 암초 충돌, 연소 완료 영역 등)
**처리**: 충격 지점·강도·재질 내구도에 따라 선체 폴리곤에서 해당 영역을 불리언 차감(carving)
**출력**: 변형된 폴리곤 → §2.1의 3대 파라미터가 **자동 재계산**됨

### 7.3 창발되는 게임플레이 (설계 목표이자 검증 항목)

1. **체감형 피해 피드백**: 좌현이 깎이면 저항 타원이 비대칭화 → 배가 저절로 좌편향. 플레이어는 HP바가 아니라 **거동 변화로 피해를 감지**한다.
2. **연쇄 상실**: 깎인 영역에 부착돼 있던 아이템은 탈락. 무게중심 이동 → 조향 특성 실시간 변화 → **항해 중 강제 재설계** 상황 발생.
3. **선체 절단 = 분리**: 폴리곤이 완전히 절단되면 **두 개의 독립 강체**가 된다. 버그가 아니라 공식 기능으로 승격한다.
4. **의도적 분리 설계 (다단 분리)**: 연결부를 얇게 그려 "잘리도록 설계된 배"를 허용한다. 예: 무거운 철제 선수부로 빙벽을 깨고 선수부를 버린 뒤, 가벼워진 본체로 얕은 여울 통과. 개발자가 "분리 기능"을 만들지 않았는데 플레이어가 발명하는 것이 목표.

### 7.4 재질별 파손 규칙

| 재질 | 파손 거동 |
|---|---|
| 나무 | 중간 내구. 연소 완료 영역은 자동 차감 |
| 철 | 고내구(대포알에 함몰만, 관통 어려움). 대신 무게 페널티 유지 |
| 고무 | 차감 대신 충격 반발(피해 무효화, 대신 반동으로 배가 밀림) |
| 얼음 | 저내구 + 열기 필드에서 시간당 자동 차감(녹음) |

### 7.5 구현 요구사항
- 폴리곤 불리언 연산 라이브러리 필요 (clipper 계열 권장).
- 차감 후 매 프레임이 아닌 **이벤트 시점에만** 파라미터 재계산 (성능).
- 절단 판정: 차감 결과가 2개 이상의 분리 폴리곤이면 각각을 독립 강체로 스폰. 아이템은 소속 폴리곤을 따라간다.
- 최소 파편 크기 미만의 조각은 소멸 처리 (물리 안정성).
- **엣지 케이스**: 무게중심이 선체 밖으로 나가는 초승달형 파손 허용(물리적으로 유효). 트리거 바인딩된 아이템이 탈락하면 해당 키는 무효화.

### 7.6 밸런싱 노트
- 파손이 항상 불리하기만 하면 재미가 반감된다. "깎여서 가벼워진 배가 여울을 통과한다" 같은 **파손의 이득 상황**을 맵 디자인에 최소 1회 이상 의도적으로 배치한다.

## 8. 맵 커리큘럼

설계 원칙: **직전 챕터의 정답을 다음 챕터의 오답으로 만든다.** 같은 규칙의 양면을 보여주는 것이 학습 곡선의 뼈대다.

| 챕터 | 맵 | 학습 목표 | 핵심 규칙 |
|---|---|---|---|
| 1 | 순풍 해협 | 그리기, 흘수, 큰 돛 | 천+바람=추력 |
| 2 | 역풍 협곡 | 돛 축소/제거, 노·부스터 도입 | 1장의 규칙이 페널티로 반전 |
| 3 | 화염 화산대 | 철 재질, 무게-흘수 재설계 | 나무+불=파괴 (파손 시스템 첫 체감) |
| 4 | 뇌우 지대 | 3장의 철배가 최악의 답(전도) → 고무 절연/나무 회귀 | 철+전기=전도 |
| 5 | 자석 요새 | 철 최소화, 또는 자기 인력을 이동에 역이용 | 철+자기=인력 (창발 해법 허용) |
| 6 | 포탑 해협 | 방어막 부착 각도 설계, 파손 관리 | 파손 지오메트리 본격 활용 |
| 7 | 빙해 여울 | **다단 분리 설계** 유도 (선수부 희생) | 절단=분리 |
| 최종 | 복합 폭풍 | 구간별 환경 변화 → 트리거 실시간 운용 | 전 규칙 종합 |

각 맵의 추가 요소: 소용돌이(슬링샷 가속 가능), 좁은 해협(형상 다이어트 강제), 얕은 여울(흘수 제약).

## 9. 기술 스택 및 구현 노트

- **물리**: Box2D 계열 2D 강체 물리.
  - 방향별 저항: 저항 타원 기반 이방성 감쇠 커스텀 구현.
  - 바람력: 노출 표면 세그먼트별 `(바람벡터 · 법선) × 길이 × 재질 풍압계수` 합산.
- **파손**: 폴리곤 클리핑 라이브러리(clipper2 등) + 이벤트 기반 재계산.
- **규칙표/재질/아이템 스펙**: 전부 JSON 데이터. 코드-데이터 분리 엄수.
- **맵 포맷**: 필드 정의(벡터/스칼라장) + 오브젝트 배치. 맵별 스크립트 금지.

## 10. 프로토타입 마일스톤

| 단계 | 내용 | 검증 질문 |
|---|---|---|
| P1 | 선체 그리기 + 3대 파라미터 + 기본 3종 장치 | 그린 모양에 따라 조작감이 실제로 달라지는가? |
| P2 | 아이템 배치(부스터·닻) + 토크 창발 조향 | 비대칭 부스터로 배가 도는가? 닻 드리프트가 성립하는가? |
| P3 | 필드(바람) + 돛 + 규칙표 최소본(불 전파 포함) | 의도하지 않은 해법이 하나라도 나오는가? |
| P4 | 파손 지오메트리 + 절단 분리 | 파손 후 거동 변화가 체감되는가? 다단 분리 배가 성립하는가? |

P1~P2에서 조작의 재미가, P3에서 창발이, P4에서 서사가 검증된다. P4까지 통과하면 수직 슬라이스 제작 착수.

## 부록 A. 용어

- **창발(Emergence)**: 개별 규칙의 조합에서 설계자가 명시하지 않은 행동·해법이 발생하는 것.
- **저항 타원**: 이동 방향별 유체 저항 계수를 타원으로 표현한 것.
- **흘수(Draft)**: 배가 물에 잠기는 깊이. 본 게임에서는 부력 계산의 스칼라 축약값.
- **팔길이(Moment arm, r)**: 무게중심에서 힘의 작용선까지의 수직 거리. 토크 = 힘 × r.
