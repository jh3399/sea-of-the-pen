단계 계획을 세우기 전에, 순서를 결정하는 원리부터 명확히 하겠습니다. 개발 순서는 "쉬운 것부터"가 아니라 **"가장 위험한 가설부터"** 입니다. 이 게임에는 틀리면 프로젝트가 무너지는 가설이 세 개 있고, 각 단계는 이 가설을 하나씩 검증하는 실험이어야 합니다:

- 가설 A: "배를 그리는 것 자체가 재미있다" (틀리면 게임 전체가 무의미)
- 가설 B: "위치 배치에서 조향이 창발한다" (틀리면 아이템 시스템 재설계)
- 가설 C: "규칙표에서 의도하지 않은 해법이 나온다" (틀리면 그냥 평범한 퍼즐 게임)

그래서 각 단계 끝에는 **통과 질문**을 붙입니다. 통과 못 하면 다음 단계로 못 갑니다.

---

## 0단계: 기술 스파이크 (1~2주)

본 개발 전에 기술 리스크만 격리해서 찔러봅니다. 세 가지 미니 실험: ① 손그림 폐곡선 → 물리 폴리곤 변환 (자기교차 보정, 정점 단순화 포함), ② 폴리곤 불리언 차감이 런타임에 안정적으로 도는지 (clipper2 검증 — 4단계의 성패가 여기 걸려 있어서 미리 확인), ③ 이방성 저항(저항 타원)을 물리 엔진 위에 커스텀 구현. 이 셋은 나중에 발견하면 아키텍처를 갈아엎게 되는 것들이라 맨 앞에 둡니다.

**통과 질문**: 세 실험이 프레임 드랍 없이 도는가?

## 1단계: 코어 필 — 그리기와 항해 (3~4주)

만드는 것: 선체 그리기 캔버스 + 실시간 오버레이(무게중심 G, 저항 타원, 흘수 게이지) / 형상 → 3대 파라미터 자동 산출 / 기본 3종 장치(키·노·닻) / 카메라(위치 추적 + 줌, 회전 금지) / 헤딩 인디케이터 + 예측 궤적선.

궤적선을 1단계에 넣는 이유: 지난 대화에서 결론 낸 심적 회전 문제를 여기서 실측해야 하기 때문입니다. 궤적선 on/off 토글을 만들어 비교합니다.

**통과 질문 (가설 A 검증)**: 아무 목표 없이 빈 바다에서, 다르게 그린 배 세 척의 조작감이 명확히 다르게 느껴지는가? 뾰족한 배와 둥근 배를 몰아본 테스터가 그 차이를 말로 설명할 수 있는가? — 여기서 재미가 없으면 멈추고 형상-물리 매핑의 과장 계수를 조정합니다. 시뮬레이션의 사실성보다 차이의 체감이 우선입니다.

## 2단계: 아이템과 창발 조향 (3~4주)

만드는 것: 아이템 부착 시스템(위치·방향·질량 통일 모델) + 부스터·닻·밸러스트 3종 / 토크 자동 계산 / 트리거 키 바인딩 UI / 설계 화면에 바인딩 키 오버레이.

아이템을 3종만 넣는 이유: 가설 B의 검증에는 "비대칭 부스터 선회"와 "닻 드리프트" 두 현상이면 충분하고, 대포·방어막·돛은 규칙표(3단계)와 얽혀 있어 지금 넣으면 실험 변수가 오염됩니다.

**통과 질문 (가설 B 검증)**: 조향 코드를 한 줄도 안 짰는데, 테스터가 좌우 부스터 배치만으로 슬라럼 코스를 통과하는가? 닻 드리프트를 스스로 발견하는 테스터가 나오는가?

## 3단계: 규칙 엔진 — 게임의 심장 (4~6주)

만드는 것: 환경 필드 시스템(바람 벡터장 우선, 해류·온도 순차 추가) / 재질 시스템(나무·철·천 3종부터) / 상태 전파(불붙음·젖음) / **JSON 규칙표 로더** / 돛 아이템(바람×천 규칙의 실증).

규칙표를 코드가 아닌 데이터로 만드는 걸 이 단계의 최우선 산출물로 삼습니다. 이후 모든 밸런싱과 콘텐츠 확장이 이 파이프라인 위에서 이뤄지기 때문에, 여기서 아키텍처가 굳습니다.

**통과 질문 (가설 C 검증)**: 화염 지대 테스트 맵에서, 의도 해법(철배) 외에 "물웅덩이를 먼저 지나 젖은 나무배로 통과" 같은 비의도 해법이 규칙 조합만으로 실제 성립하는가? 성립 안 하면 규칙표의 상성 정의를 수정합니다 — 맵에 예외 코드를 넣는 순간 원칙 1 위반이므로 금지.

## 4단계: 파손 지오메트리 (3~4주)

만드는 것: 충격 이벤트 → 폴리곤 차감 → 파라미터 재계산 파이프라인 / 절단 판정 → 다중 강체 분리 / 아이템 탈락·트리거 무효화 / 재질별 파손 거동(고무 반발, 얼음 용해 포함) / 대포·방어막 아이템 (이 단계에서 추가 — 파손의 주 원인이자 대응 수단이므로).

**통과 질문**: HP바 없이 거동 변화만으로 테스터가 자기 배의 피해 상태를 인지하는가? 그리고 결정적으로 — 연결부를 얇게 그린 다단 분리 배가 설계 의도대로 작동하는가? 이게 되면 §7의 창발 목표 달성입니다.

## 5단계: 수직 슬라이스 (4~6주)

여기서 처음으로 "게임"을 만듭니다. 커리큘럼 1~3장(순풍 해협 → 역풍 협곡 → 화염 화산대)을 완성도 있게: 맵 데이터 포맷과 에디터(개발 효율의 핵심 — 맵별 코드 0줄 원칙이 지켜지는지 여기서 판명), 설계→출항→실패→재설계 루프의 UI 완결, 실패 분석 화면(왜 침몰했는지 리플레이로 보여주기).

1~3장을 고른 이유: "규칙 학습 → 같은 규칙의 반전 → 재질 전환"이라는 커리큘럼 뼈대의 최소 단위이기 때문입니다. 이 3장이 재미있으면 나머지 맵은 같은 문법의 확장입니다.

**통과 질문**: 외부 테스터가 튜토리얼 텍스트 없이 3장까지 스스로 도달하는가? 2장에서 "1장의 정답(큰 돛)이 오답이 된다"는 반전을 즐거워하는가, 배신감을 느끼는가?

## 6단계: 콘텐츠 확장과 밸런싱 (기간은 5단계 결과에 따라)

4~최종장 맵 제작(전부 5단계 파이프라인 위에서 데이터 작업), 잔여 재질(고무·얼음)과 필드(전기·자기), 접근성(마우스 전용 트리거 버튼 바), 규칙표 밸런싱 패스. 밸런싱의 판정 기준은 원칙 2입니다: 플레이테스트에서 "항상 정답인 조합"이 발견되면 그 조합에 약점을 추가합니다.

전체 흐름을 한 줄로 요약하면: **0단계에서 기술 리스크를, 1~4단계에서 세 가설을 하나씩, 5단계에서 "이게 게임이 되는가"를, 6단계에서 "얼마나 깊은가"를 검증합니다.** 대략 5~7개월 분량이고, 각 단계의 통과 질문이 곧 중단/피벗 판단 기준입니다.
